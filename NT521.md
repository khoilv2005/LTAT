# NT521 - Tổng hợp thực nghiệm ChatGPT-Vulnerability-Management

## 1. Mục tiêu và trạng thái chung

Repo này tái hiện 6 task trong paper USENIX Security 2024 về việc dùng ChatGPT cho vulnerability management:

1. Bug report summarization
2. Security bug report identification
3. Vulnerability severity evaluation
4. Vulnerability repair
5. Patch correctness assessment
6. Stable patch classification

Trạng thái hiện tại: code đã hỗ trợ cả 6 task theo preset tốt nhất của paper. Đã chạy thực nghiệm với model `deepseek-v4-flash:cloud` qua Ollama cloud API. Không có bước train/fine-tune model. Tất cả đều là prompt-based inference.

Thực nghiệm trong repo này chỉ thực hiện Phase 3 của paper, tức large-scale evaluation trên test set. Repo không tái hiện đầy đủ Phase 1 và Phase 2, vì Phase 1/2 là quá trình paper dùng để thiết kế nhiều prompt templates và chọn prompt tốt nhất trên probe-test. Ở đây, ta lấy trực tiếp prompt strategy tốt nhất mà paper đã báo cáo, rồi chạy lại trên test set với model khác.

Task 1 chưa chạy hết do job quá lớn và đã dừng sớm. Task 4 chỉ đo được output generation, chưa đo được correctness theo paper vì repo thiếu full VulFix harness gồm source gốc, compile script, PoC security test, regression/functional test.

## 2. Paper dùng như thế nào

Paper dùng `gpt-4-0314`, `temperature = 0`, `top_p = 1.0`. Các prompt tốt nhất theo paper:

| Task | Input | Output | Prompt tốt nhất trong paper |
|---|---|---|---|
| 1. Bug report summarization | bug report | title/summary | few-shot với GPT-4 |
| 2. Security bug report identification | bug report | SBR/NBR | expertise với GPT-4 |
| 3. Vulnerability severity evaluation | function + description | CVSS metric label AV/AC/PR/UI | self-heuristic với GPT-4 |
| 4. Vulnerability repair | vulnerable code snippet + error/vuln info | repaired code | expertise với GPT-4 |
| 5. Patch correctness assessment | patch/code/description tùy dataset | correct/incorrect patch | code-only hoặc self-heuristic tùy dataset |
| 6. Stable patch classification | patch description + code snippet | stable/non-stable | expertise với GPT-4 |

### 2.1 Các prompt strategy nghĩa là gì

Paper không train/fine-tune model. Paper thay đổi cách viết prompt để xem cách nào giúp ChatGPT làm task tốt hơn. Ba cách quan trọng nhất trong repo hiện tại là `few-shot`, `expertise`, và `self-heuristic`.

#### Few-shot

`few-shot` nghĩa là trong prompt có kèm một vài ví dụ mẫu đã có input và output đúng. Model nhìn các ví dụ đó để học format trả lời và pattern của task ngay trong context.

Ví dụ với Task 1 bug report summarization:

- Prompt đưa vài bug report mẫu và title/summary đúng tương ứng.
- Sau đó đưa bug report mới.
- Model phải sinh title/summary cho bug report mới theo kiểu đã thấy trong ví dụ.

Trong code, `few-shot` được xử lý trong `src/prompt.py` khi gọi `prompt.generate_prompt(...)`. Với Task 1, method tốt nhất theo paper là `few-shot`, nên lệnh chạy là dạng:

```powershell
python run.py --task title --dataset title_itape --method few-shot --TEST test --testNum 0
```

Few-shot phù hợp với task output dạng ngôn ngữ tự nhiên, vì ví dụ giúp model bắt chước độ dài, phong cách, và thông tin cần giữ lại.

Ví dụ prompt thực tế của Task 1:

```text
Generate a title for this bug report in one short sentence.

Bug report: @ caesarxuchao reports that gke cluster can not up with verid40 1.7 verid0 branch...
Title: e2e gke cluster can not up in both master and 1.7 branch
###
Bug report: i have the following `.babelrc` file and am using `@ babel` 8.x+ packages...
Title: babel-preset-env - how to disable node target for browser-only (.browserslistrc)
###
Bug report: hi, i report you an issue with any version of jquery...
Title:
```

Ví dụ trên có 2 cặp `Bug report -> Title` làm demonstration. Bug report cuối là mẫu test cần model sinh title. Ground truth của mẫu test đầu tiên trong repo là:

```text
the selector target the wrong element when an id is n't unique in the dom
```

#### Expertise

`expertise` nghĩa là prompt có thêm domain knowledge/luật chuyên môn viết sẵn bởi người thiết kế. Model không tự rút luật từ dữ liệu, mà được nhắc trực tiếp các tiêu chí cần dùng để phân loại hoặc sửa lỗi.

Ví dụ với Task 2 security bug report identification:

- Prompt mô tả model là chuyên gia security.
- Prompt đưa tiêu chí phân biệt security bug report và non-security bug report.
- Input là một bug report mới.
- Output cần là `SBR` hoặc `NBR`.

Trong code, `expertise` cũng được sinh qua `src/prompt.py`. Các task dùng `expertise` hiện tại:

- Task 2: SBRP, output `SBR/NBR`.
- Task 4: VulFix, output repaired code.
- Task 6: stable patch classification, output stable/non-stable.

Lệnh chạy có dạng:

```powershell
python run.py --task SBRP --dataset Ambari --method expertise --TEST test --testNum 0
```

Expertise hữu ích khi task cần kiến thức miền rõ ràng, ví dụ security concept, dấu hiệu vulnerability, stable patch rule, hoặc nguyên tắc sửa vulnerability.

Ví dụ prompt thực tế của Task 2 `SBRP/Ambari`:

```text
SYSTEM:
You are Frederick, an AI expert in bug report analysis. Your task is to decide whether a given bug report is a security bug report (SBR) or non-security bug report (NBR). When analyzing the bug report, take into account that bug reports related to memory leak or null pointer problems should be seen as security bug report.

USER:
A security bug report is a bug report describing one or more vulnerabilities of a software system. Besides, bug reports that directly mention "memory leak" or "null pointer" problems must be seen as security bug reports.

USER:
For the bug report:
Out of memory issues with Request API on large cluster
Number of ExecutionCommandEntity objects keep growing and result in Out of memory on large cluster (100 nodes)...

Is this bug report (A) a security bug report (SBR), or (B) a non-security bug report (NBR).

Answer: Let's think step-by-step to reach the right conclusion,
```

Ground truth của ví dụ này là `1`, tức `SBR`. Expertise ở đây là luật "memory leak/null pointer phải xem là security bug report", nên model được hướng rõ cách phân tích.

#### Self-heuristic

`self-heuristic` là cách 2 vòng. Model tự đọc một số ví dụ có label, tự rút ra heuristic/rule, rồi dùng các heuristic đó để phân loại test set.

Pipeline:

1. Round 1: lấy samples từ `probe` hoặc `train`.
2. Đưa samples đó cho model và yêu cầu model tóm tắt đặc điểm từng class.
3. Lưu rule/heuristic vào `results/heuristics/<task>_<dataset>_heuristics.json`.
4. Round 2: chèn rule vừa rút ra vào system prompt.
5. Chạy model trên `test` split để lấy prediction.

Trong code, pipeline này nằm ở `run_self_heuristic.py`:

- `prompt.extract_heuristics(...)`: chọn ví dụ từ `probe`/`train`, tạo prompt yêu cầu rút rule.
- `call_chat_api(...)`: gọi API để lấy heuristic text.
- `prompt.generate_self_heuristic_system_prompt(...)`: nhét heuristic vào system prompt.
- `request.async_api_requests(...)`: chạy classification trên test set.

Lệnh chạy có dạng:

```powershell
python run_self_heuristic.py --task cvss --dataset AV --testNum 0
```

Các task hiện dùng `self-heuristic`:

- Task 3: CVSS AV/AC/PR/UI.
- Task 5: APCA Invalidator và Panther.

Điểm khác với few-shot: few-shot đưa ví dụ trực tiếp vào prompt test; self-heuristic dùng ví dụ để tạo rule trước, rồi prompt test chỉ chứa rule đã tổng hợp.

Điểm khác với expertise: expertise dùng rule do người viết sẵn; self-heuristic dùng rule do model tự rút ra từ dữ liệu probe/train.

Ví dụ thực tế của Task 3 `cvss/AC`:

Round 1 lấy ví dụ từ `data/cvss/AC-probe.json`, rồi hỏi model tự rút rule:

```text
Below are some examples of source code functions and their corresponding AC labels:

[Not High (Class 0)]:
  - Function: amiserial_console_init
    Description: register console...
  - Function: ath5k_setup_rate_powertable
    Description: set up rate power table...

[High (Class 1)]:
  - Function: write_seqlock
    Description: start seqlock write side critical section...
  - Function: ixgbe_acquire_swfw_sync_X540
    Description: acquire swfw semaphore...

Your task: briefly summarize the "Identifying Characteristics" for each AC class.
```

Model rút ra heuristic và lưu ở `results/heuristics/cvss_AC_heuristics.json`. Một đoạn heuristic thực tế:

```text
Class 0 (Not High): Functions are typically simple initialization, setup, teardown, registration, or single-purpose operations...

Class 1 (High): Functions involve acquiring or releasing locks, semaphores, or mutexes; checking status or conditions with atomicity; or managing concurrency...
```

Round 2 dùng heuristic đó để test mẫu mới:

```text
SYSTEM:
You are Frederick, an elite AI cybersecurity expert specializing in vulnerability severity evaluation based on CVSS v3.1 standards.

To ensure extreme accuracy, you MUST strictly follow this domain knowledge when making your decision:
[heuristics vừa trích xuất]

CLASSIFICATION OPTIONS:
(A) Not High, (B) High

USER:
Function: down_timeout
Function description: acquire the semaphore within specified time...

Based on the expert knowledge provided, classify the function.
Output final answer EXACTLY:
**Answer: (X) Label**
```

Ground truth của mẫu `down_timeout` là `1`, tức `High`.

#### Code-only

`code-only` nghĩa là prompt chủ yếu đưa code/patch cần đánh giá, không thêm nhiều mô tả hay expertise. Trong repo hiện tại, cách này dùng cho Task 5 Quatrain vì paper thấy code-only tốt nhất trên dataset đó.

Ví dụ prompt thực tế của Task 5 `APCA_quatrain`:

```diff
Patch:
--- /src/main/java/org/apache/commons/math3/distribution/FDistribution.java
+++ /src/main/java/org/apache/commons/math3/distribution/FDistribution.java
@@ -272,7 +272,7 @@
     public boolean isSupportLowerBoundInclusive() {
-        return true;
+        return false;
     }

--- /src/main/java/org/apache/commons/math3/distribution/UniformRealDistribution.java
+++ /src/main/java/org/apache/commons/math3/distribution/UniformRealDistribution.java
@@ -181,7 +181,7 @@
     public boolean isSupportUpperBoundInclusive() {
-        return false;
+        return true;
     }

Category: (A) The patch correctly fixes a bug (CoF), or (B) The patch does not correctly fix a bug (NCF).
Answer: Please think step-by-step to reach the right conclusion,
```

Ground truth của patch này là `1`, tức `CoF`/correct patch. Điểm chính của `code-only`: model chủ yếu dựa vào diff code, không dựa vào mô tả bug dài hoặc rule tự rút.

## 3. Code hiện tại làm gì

### 3.1 Prompt generation

File chính: `src/prompt.py`.

`prompt.generate_prompt(...)` đọc dataset từ `data/`, tạo message list cho từng task, gắn `ground_truth`, `id`, và prompt method:

- `few-shot`: chèn ví dụ minh họa vào prompt.
- `expertise`: chèn domain expertise viết sẵn vào system/user prompt.
- `self-heuristic`: cần có heuristics đã trích xuất, sau đó chèn vào system prompt.
- `code-only`: chỉ đưa code/patch content cần đánh giá.

File `paper_tasks.py` lưu preset paper-aligned cho 6 task. File này dùng để dry-run prompt hoặc in command tương ứng với GPT-4 paper setting.

### 3.2 Chạy inference bình thường

File chính: `run.py`.

Luồng xử lý:

1. Đọc tham số task/dataset/method/model/API.
2. Gọi `prompt.generate_prompt(...)`.
3. Nếu `--dry_run` thì chỉ in preview prompt.
4. Nếu chạy thật thì gọi `src/request.py::async_api_requests(...)`.
5. Lưu result JSON vào `results/`.

Không train model. `run.py` chỉ tạo prompt và gọi chat completion API.

### 3.3 Chạy self-heuristic

File chính: `run_self_heuristic.py`.

Pipeline 2 round:

1. Round 1: dùng probe/training examples để hỏi model tự rút ra heuristics. Mặc định `n_samples_per_class = 30`.
2. Cache heuristics vào `results/heuristics/<task>_<dataset>_heuristics.json`.
3. Round 2: chèn heuristics vào system prompt.
4. Chạy classification trên test set bằng `request.async_api_requests(...)`.

Đây là cách repo hiện tại làm Task 3 và một phần Task 5 theo paper.

### 3.4 Gọi API

File chính: `src/request.py`.

Config hiện tại cho thực nghiệm:

- API URL: `https://ollama.com/api/chat`
- Model: `deepseek-v4-flash:cloud`
- `temperature = 0`
- `top_p = 1`
- `stream = false`
- Ollama payload có `think = false`
- `options.num_predict = min(response_max_token or max_token, 1024)`
- timeout request: total 60s, connect 20s, read 45s
- có resume: đọc result cũ, bỏ qua ID đã có kết quả hợp lệ
- có atomic write, backup, flush mỗi `save_every`
- có rate limit và concurrency

Script chạy full: `run_full_deepseek.ps1`.

Default script:

- `Model = deepseek-v4-flash:cloud`
- `ApiUrl = https://ollama.com/api/chat`
- `Rate = 10` requests/min
- `TokenRate = 1000000`
- `MaxConcurrent = 2`
- label task cap response 64 tokens
- title cap response 32 tokens
- repair cap response 1024 tokens
- `save_every = 500`

Thứ tự chạy ưu tiên task nhỏ trước, title lớn nhất chạy cuối.

### 3.5 Evaluation

File chính: `eval.py`.

Metric hiện tại:

- Task 1: ROUGE-1/ROUGE-2/ROUGE-L F1.
- Task 2: classification metrics, positive class SBR có Recall, FPR, Precision, F1, G-measure.
- Task 3: accuracy, macro-F1, per-class precision/recall cho từng CVSS metric.
- Task 4: chỉ đếm response/code-like output. Chưa paper-equivalent.
- Task 5: accuracy, +Recall, -Recall, Precision, F1, AUC.
- Task 6: accuracy, Precision, Recall, F1, AUC.

File tổng hợp hiện tại: `tools/evaluate_current_metrics.py`.

Output hiện tại: `results/metrics/deepseek_v4_flash_metrics_current.json`.

### 3.6 Dataset, train/probe/test, và split đã chạy

Lưu ý quan trọng: repo không train/fine-tune model. Từ "train" trong dataset chỉ là split dữ liệu có sẵn để thiết kế prompt, lấy demonstration examples, hoặc trích xuất heuristics cho self-heuristic. Final evaluation hiện tại đều chạy trên `test` split bằng `--TEST test --testNum 0` hoặc tương đương trong `run_self_heuristic.py`.

Trong pipeline paper, `training dataset` dùng để thiết kế prompt templates, `probe-test dataset` dùng chọn best template, và `test dataset` dùng large-scale evaluation. Trong repo hiện tại:

- `run.py` với `few-shot`, `expertise`, `code-only` gọi API trên `test` split.
